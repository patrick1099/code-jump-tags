## 为什么封存（YAGNI 复盘）

关键认识：**「私有注释、不进 commit」这个需求，Code Jump Tags 现在就已经满足**——标签存 sidecar（`.code-jump-tags/store.json`，gitignore 即可），源码不动、能跳转、能分文件夹、能列全部。

所以拟建的新功能（下称 **C**）**真正新增的只有一样**：输入手势——敲 `//me:` 比「进编辑模式→点 gutter→弹框打字」更顺。而这份"顺"的代价，恰是整个设计里最难最险的一块（双向改文件 + undo 交织）。性价比存疑，故先验证。

### 三条路对比

| | 做什么 | 私有不提交 | 跳转/树/整理 | 代码干净度 | 成本 |
|---|---|---|---|---|---|
| **A. 用现有 CJT** | 点 gutter 打标签 | ✅ | ✅ | ✅ 悬浮小字 | 0；输入重一点 |
| **B. git clean filter**（本次实验选用）| 敲 `//me:` 留代码里，filter 剥掉 | ✅ | ❌ | ❌ 满屏 `//me:` 原文 | 一次 git 配置，0 代码 |
| **C. 建这个功能** | 敲 `//me:` → 悬浮标签 | ✅ | ✅ | ✅ | 大量开发 + undo 风险 |

- A 是真 YAGNI 基线：想要的几乎都有了，缺的只是打标签慢一点。
- B 几乎零成本给你"自然输入"，代价是代码里留 `//me:` 原文（占地方、进 minimap、碍眼）、无整理。
- C 是唯一"输入顺 + 渲染干净 + 能整理"三者全要的——但只有它需要那套有风险的双向改文件。

## 实验：git clean filter 配置（B 方案）

对**想写私记的那个仓库**本地生效，什么都不提交（配置写在 `.git/config` 与 `.git/info/attributes`，二者都不进版本库）。

以 C/JS 的 `//` 注释符为例：

```bash
# 1. 定义 filter：把行尾的 //me:... 剥到行尾（本地 .git/config）
git config filter.stripme.clean "sed 's|[[:space:]]*//me:.*$||'"

# 2. 让它作用到所有文件（本地 .git/info/attributes）
echo '* filter=stripme' >> .git/info/attributes
```

效果：工作区里敲 `code //me: 私记`，但 `git diff` / `git add` / commit 看到的都是剥干净的 `code`。

### 提醒 / 坑

- **按语言换注释符**：Python 用 `#me:`（sed 换成 `s|[[:space:]]*#me:.*$||`）。
- **独占一行的 `//me:` 会被剥成空行**（留 whitespace diff）。想连空行也删就用整行删版 `/^[[:space:]]*\/\/me:/d`，但那个不能处理行尾形态。**行尾是主场景，用上面的剥到行尾版。**
- **验证**：配好后加一条 `//me:` 存盘，跑 `git status`，应当**看不到**这条 diff。
- **误伤**：字符串字面量里的 `//me:`（如 `"http://me:x"`）也会被剥——实验期接受，真困扰再说。
- **本机专属**：filter 每台机器单独配、不随仓库走。对"就我自己本机用"反而正好，天然不外泄；但对 `git stash`、部分暂存、blame 行号偶尔有轻微意外，无伤大雅。

## 实验要观察什么（2 周后据此定夺）

1. **我到底会不会持续写 `//me:` 注释？** —— 没怎么写 ⇒ 需求是伪的，C 不必建，spec 归档。
2. **满屏 `//me:` 原文（B 的杂乱）烦不烦？** —— 很烦、且我确实写了一堆 ⇒ 需求被真实的痛证实，C 师出有名，回来建。
3. **A（现有 gutter 流）是不是其实也够？** —— 如果发现点 gutter 也不算慢，那连 B 都不用长期留。

## 如果将来决定建 C：接手须知

- **设计已定稿**：见 `2026-07-05-inline-me-notes-design.md`。v1 只做行尾；v2 上方注释走 CodeLens、边界隔离方便回退；「留空行」方案连同三选二死结推理已记为**已否决**，别重开。
- **undo 风险的结论（重要）**：VS Code **无法**让扩展做"不进 undo 栈"的编辑，所以 undo **做不到隐形**；但能**无害化**——
  - 折叠幂等 + 每个落定点重跑 ⇒ 游离的 `//me:` 自愈，**堵死泄漏**；
  - 单段可逆编辑 ⇒ **不改坏代码**；
  - `undoStopBefore/After:false` + 靠光标进出触发 ⇒ 减少突兀。
  - 残留仅"偶尔多按一次撤销 / `//me:` 闪一下"的外观毛刺，**非数据/隐私问题**。
  - 实现计划里须把「undo 交织行为」列为显式**验收项**。
- **下一步就是** `writing-plans`：把 v1 拆成带 TDD 的实现计划（纯函数 `parseInlineNote`/`stripInlineNote`/`toInlineText` 先行）。
